# 複数サンプルによる北キャリブレーション

通常の `/calibration` とDebugの実機用「北基準を合わせる」は、同じ `useNorthCalibrationSampling` / `calibrationSampling.ts` を使う。従来は約700ms保持した後の最後の1サンプルを保存していたが、安定した期間の補正候補を集約して保存する方式へ変更した。

## 収集と集約

入力は `useDeviceOrientation` の `diagnostics.lastAccepted` のみ。各イベントのalpha / beta / gammaと、同じイベントのwebkitCompassHeadingを既存 `getHorizontalCalibration` に渡し、candidateNorthCorrectionを計算する。画面用stateの値を別々に読み合わせず、無視されたイベントも使用しない。

初期待機500msの後、2.5秒以上・有効20件以上で確定する。100ms以上の間隔で採用するため通常は約26件。件数不足の場合は最大3秒まで待ち、それでも不足する場合は測り直す。開始待機を含め通常は約3秒で保存する。同じ値でも新しいイベントなら採用できるが、再描画や時計から同じイベントを増殖させない。

最大の空白区間で円を切り、観測値が占める区間を数直線へ展開して中央値を取る。359° / 1°は0°付近、179° / −179°は180°付近へ集約される。狭い区間だけがばらつき検査を通るため、有効な集合では円周上の中央値になる。保存値は既存と同じ `[-180°, 180°)` に正規化する。

保存するのは集約後のnorthCorrectionと既存のcalibratedAtのみ。サンプルやWMM値は保存済み補正へ追加しない。通常画面は成功後600msでARへ移動する。Debugはボタン操作後だけ収集し、成功すると収集要求を終了する。継続して補正を更新しない。

## 除外と測り直し

閾値は `src/features/north-calibration/calibrationSampling.ts` の `CALIBRATION_SAMPLING_LIMITS` に集約する。

| 条件 | 処理 |
| --- | --- |
| 非有限の姿勢、コンパス欠測・無効値、既存のhorizontalLength ≥0.9を満たさない | 採用せず、部分的な収集も破棄 |
| 有効な前回値に対してheading / beta / gamma / candidateが8°超急変 | 急変したサンプルを除外。外れ値を次の比較基準にしない |
| candidate / heading / beta / gammaの円周rangeが各6°超 | 破棄し、安定した期間を最初から測り直す |
| 有効値が500ms超途切れる、古い入力、時刻の巻き戻り | 破棄し、待機後に再開 |
| 画面回転、visibility変更、pagehide / pageshow | 即座に破棄し、500ms後に新しいイベントから再開 |
| eventTypeまたはabsoluteによる取得元の変更 | 切り替え時のイベントを捨て、500ms後に再開 |
| 有効件数20未満、観測時間2.5秒未満 | 保存しない |

単発の大きな外れ値は除外し、残りの十分な安定サンプルで集約できる。小さな外れ値が残っても中央値なので最後の1点や平均ほど引っ張られない。外れ値が続いたり、ゆっくり大きく動いてrangeが広がる場合は、古い期間の時間を借りて確定しない。

## accuracyと変更範囲

- −1などの負値は未校正として確定保留。
- 20°超や非有限の値は確定保留。使える値に戻れば新たに収集する。
- 未提供は非対応として区別する。accuracyを提供しない端末でも、安定した有効サンプルが揃えば完了できる。

accuracyによる角度の重み付け、WMM補正、ライブコンパスへの常時追従は追加しない。AR、天文計算、月の投影、北補正の適用行列、保存先Providerの寿命は変更しない。

Debugの「この方向を北にする」は、PC手動入力やコンパス非対応時にユーザーが既知の北を明示する別操作として維持する。

この改善は短時間の揺れや単発の外れ値を保存する可能性を減らすもの。安定した10°級の絶対方位バイアスを直す機能でも、長期ドリフトの追従補正でもない。

## 実機確認

1. HTTPSで `/calibration` を開き、必要なら向きセンサーを許可する。
2. スマホ背面を地平線付近へ向け、約3秒静止する。「測定しています」と進捗が表示され、成功後ARへ移ることを確認する。
3. 別の試行で測定中に端末を大きく動かし、「もう少し静止してください」となって途中では確定しないことを確認する。
4. 測定中に縦横を切り替える、または一度バックグラウンドへ移る。復帰後に古い進捗を使わず、新しく測定することを確認する。
5. Debugの「北基準を合わせる」でも、クリック直後ではなく同じ測定期間の後に保存されることを確認する。
6. 同じ目標・姿勢で数回繰り返し、保存値の再現性を比較する。比較中は照準と周囲の磁気環境をそろえる。
7. 安定していても絶対方位が合う保証にはしない。必要なら既知ランドマークのTrue bearingと別途比較する。
