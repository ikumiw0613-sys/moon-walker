# コンパス・場所比較の診断

Debug 画面を、A: 状態概要、B: コンパス・保存済み北基準、C: 磁気環境診断、D: 端末姿勢、E: 重力・DeviceMotion、F: 月の変換経路、G: 太陽・スカイツリー・月相に整理した。
行列、ベクトル、操作用コントロールは詳細の折りたたみから確認できる。月の診断コピーと、従来の投影プレビューも維持する。

## 統計と品質

- 採用済み実機 orientation イベントから最大10Hzで収集する。直近3秒・最大30件を保持する。
- candidate と heading: 有効件数、中央値、円周上の最短包含区間の端点、区間幅 range、区間内標準偏差を表示する。
- accuracy: 現在の生値、有効値の中央値、最小・最大、件数を表示する。負値・非有限値・未対応は有効値に含めない。
- 角度の最大空白区間で円周を切り、残る区間の中央を基準に `normalizeSignedAngle(sample - reference)` で展開して統計を取る。359° と1° の range は2°、中央値は0°になる。candidate は表示時に±180°の表記へ戻す。

判定用のばらつきには標準偏差ではなく **angular range** を使用する。初期閾値は `src/features/debug/compassDiagnostics.ts` に集約している。

| 品質 | 条件 |
| --- | --- |
| GOOD | accuracy ≤10°、candidate と heading の range が両方≤3° |
| CAUTION | 必要データが揃い、GOOD・POOR の条件に該当しない |
| POOR | accuracy >20°、または candidate / heading のいずれかの range >8° |
| UNAVAILABLE | 各10件未満、現在の有効値不足、手動テスト、更新停止、ページ非表示 |

accuracy は現在値と直近中央値の大きい方を使う。1秒を超える更新停止では判定を停止し、古い統計を現在の品質として表示しない。ページの非表示・再表示時には履歴をクリアする。

端末を実際に回せば heading range も増える。数秒静止して比較すること。GOOD でも一定の磁気バイアスは検出できず、真北との一致や磁気干渉の不在を保証しない。重力差は傾きの検証であり、yaw の誤差を検出しない。

## 場所比較の記録

「現在の診断を記録」で、クリック時刻、緯度経度と位置取得時刻、コンパス値、保存済み補正、候補中央値・range、heading range、重力差、補正後の向き、月の方位高度、品質・理由、サンプル数、観測時刻・時刻モード、入力元、任意メモを固定保存する。

最新10件をカードで並べ、古い記録から自動的に削除する。個別削除・全消去に対応する。ブラウザーの永続ストレージには保存せず、Debug を離れるかページを更新すると消える。

## 実機確認

1. HTTPS の Debug を開き、手動テストをOFF、センサーを有効にする。時刻モードは「現在時刻」にする。
2. 開けた屋外で現在地を取得し、従来どおり北基準をキャリブレーションする。重力差も比較する場合は加速度センサーを有効にし、詳細から符号を確認する。
3. 端末を同じ向きで約3秒静止させ、「開けた場所」「月と一致」などのメモを入力して記録する。
4. 建物横へ移動し、現在地を再取得する。保存済み北補正を維持したまま約3秒静止して記録する。
5. 金属フェンス、手すり、車、電気設備付近でも同様に記録する。
6. accuracy / candidate range / heading range / 品質 / 保存値と候補中央値の差を比較する。実際の月とのズレもメモする。
7. 手動テストON、センサー更新停止、accuracy未対応の端末では UNAVAILABLE になることも確認する。

本番ARの月位置計算、northCorrectionの保存・適用、moonWorld、moonInDevice、projection、キャリブレーション確定条件は変更していない。新しい Compass Quality は Debug の表示・比較にのみ使用し、本番の拒否条件には使用しない。

自動テストは角度跨ぎ、閾値、欠測、更新停止、実イベントの採用と重複排除、記録の固定・件数制限・削除、および既存のDebug / AR出力一致を対象とする。磁気環境による実際の月とのズレは実機で確認する。
